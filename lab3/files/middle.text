1. ВВЕДЕНИЕ В СИСТЕМНЫЙ УРОВЕНЬ
Разработка системного ПО на ассемблере x86_64 под Linux — это не просто написание команд,
это управление ресурсами центрального процессора и операционной системы напрямую. 
Когда ты пишешь лексер или библиотеку системных вызовов (как твои syscalls.inc), 
ты работаешь в пространстве, где каждый байт и каждый такт процессора имеют значение.

2. ТЕОРИЯ И ПРАКТИКА КОНЕЧНЫХ АВТОМАТОВ (FSM)
Лексер (лексический анализатор) — это программная реализация детерминированного 
конечного автомата (DFA). Его задача: преобразовать сырой поток байтов в токены.

Для реализации эффективного лексера на ASM обычно используют три подхода:

A. Вычисляемые переходы (Computed Jumps):
Создается таблица переходов, где индекс — это код символа (0-255). 
Это позволяет достичь скорости O(1).
Пример логики:
   movzx rax, byte [read_buffer + rdx]
   jmp [dispatch_table + rax * 8]

B. Табличный автомат:
Состояние хранится в регистре, а следующее состояние берется из заранее 
подготовленной матрицы состояний.
   next_state = transition_matrix[current_state][input_char]

C. Жесткая логика (Hardcoded):
Использование цепочек cmp/jcc. Это то, что ты сейчас реализуешь через макросы 
if/while. Это проще в отладке, но сложнее в поддержке при росте грамматики.

3. ГЛУБОКИЙ АНАЛИЗ SYSCALL В LINUX X86_64
Системный вызов — это дорогостоящая операция перехода из Ring 3 (User Mode) 
в Ring 0 (Kernel Mode).

Особенности, которые ломают код новичков:
- Регистр RAX: Содержит номер системного вызова на входе и результат на выходе.
- Регистр RCX: Ядро затирает его значением RIP (адрес возврата).
- Регистр R11: Ядро затирает его текущими флагами процессора (RFLAGS).
- Caller-saved регистры: Ядро может изменить RDI, RSI, RDX, R10, R8, R9.

Правило выживания в ASM:
Если тебе нужно, чтобы значение (например, дескриптор файла или указатель на объект) 
пережило вызов syscall внутри цикла, храни его в CALLEE-SAVED регистрах:
RBX, RBP, R12, R13, R14, R15. Операционная система обязана вернуть их в 
исходном состоянии.

4. ОПТИМИЗАЦИЯ ПОД АРХИТЕКТУРУ INTEL COFFEE LAKE (i5-9600)
Твой процессор обладает сложной структурой конвейера и предсказателя переходов.
Чтобы код работал максимально быстро:

- Выравнивание (Alignment): Всегда выравнивай метки циклов по границе 16 байт 
  используя директиву `align 16`. Это ускоряет выборку инструкций (Instruction Fetch).
- Macro-fusion: Intel умеет объединять пару инструкций (например, CMP и JNE) 
  в одну микрооперацию (uOp). Не вставляй другие команды между сравнением и переходом.
- Избегай Partial Register Stall: Не смешивай работу с 8-битными (AL, R8B) 
  и 64-битными (RAX, R8) регистрами одного имени слишком часто, это может 
  вызвать задержку на объединение данных в конвейере.

5. СТРАТЕГИИ ОБРАБОТКИ БУФЕРА (4096 БАЙТ)
Использование BUFFER_SIZE = 4096 оптимально, так как это размер одной 
страницы памяти в Linux. Чтение меньшими порциями увеличивает количество 
переключений контекста, что катастрофически замедляет программу.

При поиске символа (например, '\n' - код 10):
Вместо:
   loop: lodsb / cmp al, 10 / jne loop
Лучше использовать:
   REPNZ SCASB — это встроенная инструкция поиска, которая на современных 
   процессорах Intel оптимизирована на микропрограммном уровне.

6. УПРАВЛЕНИЕ ПАМЯТЬЮ И MMAP
Вместо устаревшего sys_brk для выделения памяти под твое дерево синтаксиса (AST) 
в будущем лучше использовать sys_mmap (номер 9).
Это дает:
- Возможность задать права доступа (Read/Write/Execute).
- Легкое освобождение памяти целыми блоками.
- Поддержку "ленивого" выделения (память не выделяется физически, пока ты 
  к ней не обратишься).

7. СОВЕТЫ ПО РЕАЛИЗАЦИИ РЕГУЛЯРНЫХ ВЫРАЖЕНИЙ НА ASM
Если ты пишешь компилятор регулярных выражений:
1. Построй NFA (недетерминированный автомат) на основе регулярного выражения.
2. Преобразуй его в DFA (детерминированный автомат).
3. Сгенерируй код на ассемблере, который представляет собой этот DFA. 
   Это будет работать быстрее, чем любой интерпретатор (как в Java или Python).

8. РЕКОМЕНДАЦИИ ПО ОТЛАДКЕ
Используй утилиту `strace`. Запуск `./lab3 input.txt` через `strace ./lab3` 
покажет тебе реальные аргументы, которые попадают в ядро. Ты сразу увидишь, 
если в RDX (количество байт) попала единица вместо ожидаемых 34.

9. ЗАКЛЮЧЕНИЕ
Ассемблер не прощает ошибок в логике регистров, но дает абсолютную власть 
над "железом". Твой текущий проект по созданию модульной библиотеки сисколлов 
и циклов — это отличный фундамент для понимания того, как на самом деле 
работают высокоуровневые языки вроде Java и ее JVM.
